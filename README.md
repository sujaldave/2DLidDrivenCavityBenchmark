# svMultiPhysics 2D lid-driven-cavity benchmark

This benchmark reproduces the square-cavity results of Ghia, Ghia, and
Shin (1982) at Reynolds numbers 100, 400, 1000, and 5000. It is intended
for periodic solver validation and regression testing rather than for a
short per-commit unit test.

One command creates the meshes and solver inputs, runs svMultiPhysics, and compares the final velocity fields with literature data:

```bash
./allRun
```

The workflow produces machine-readable error metrics and exactly seven
figures: two centerline comparisons, one primary-vortex comparison, and
four streamline plots.

## Reference problem

The nondimensional domain is the unit square. The top wall moves from left to right with unit velocity; the other walls are stationary.

```text
                       u = 1, v = 0
                (0,1) -------------- (1,1)
                      |              |
                      |      y       |
          u=v=0       |      ^       |       u=v=0
                      |      |       |
                      |      +--> x  |
                (0,0) -------------- (1,0)
                           u=v=0

                    L = U = rho = 1
                    mu = 1 / Re
```

Reference:

> U. Ghia, K. N. Ghia, and C. T. Shin, “High-Re solutions for
> incompressible flow using the Navier–Stokes equations and a multigrid
> method,” *Journal of Computational Physics* 48 (1982), 387–411.
> <https://doi.org/10.1016/0021-9991(82)90058-4>

The comparison uses Table I for `u(0.5,y)`, Table II for `v(x,0.5)`, and
Table V for the primary-vortex center. The CSV files under `literature/`
are direct transcriptions of the published tables.

## Included cases

| Re | Grid points | Q1 quadrilaterals | Viscosity | Time step | Steps | Final time |
|---:|---:|---:|---:|---:|---:|---:|
| 100 | 129 x 129 | 128 x 128 | 0.01 | 0.02 | 5,000 | 100 |
| 400 | 129 x 129 | 128 x 128 | 0.0025 | 0.02 | 5,000 | 100 |
| 1,000 | 129 x 129 | 128 x 128 | 0.001 | 0.01 | 10,000 | 100 |
| 5,000 | 257 x 257 | 256 x 256 | 0.0002 | 0.005 | 20,000 | 100 |

The meshes use bilinear quadrilateral elements and contain
`GlobalNodeID` and `GlobalElementID` arrays. Four VTP boundary files are
generated for each case. The top face is assigned twice in `solver.xml`,
once for each effective direction. The `(1,0)` entry prescribes the unit
horizontal lid velocity, while the `(0,1)` entry explicitly prescribes zero vertical velocity and enforces no penetration.

## Requirements

- Python 3.10 or newer
- NumPy
- Matplotlib
- VTK Python bindings
- svMultiPhysics available as `svmultiphysics`, or supplied through
  `SVMP_BIN`
- an MPI launcher such as `mpirun`

Install the Python dependencies into an isolated environment:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

If an existing SimVascular/VTK conda environment is used, point `PYTHON`
to that environment's interpreter when invoking `allRun`.

## Run the complete benchmark

From this directory:

```bash
SVMP_BIN=/absolute/path/to/svmultiphysics \
PYTHON=/absolute/path/to/python \
NP=8 \
./allRun
```

Environment variables:

| Variable | Default | Purpose |
|---|---|---|
| `PYTHON` | `python3` | Python interpreter used by all scripts |
| `SVMP_BIN` | `svmultiphysics` | Solver executable |
| `MPIEXEC` | `mpirun` | MPI launcher |
| `NP` | `8` | MPI process count |

The cases run sequentially so that each simulation receives all requested
MPI processes. The full benchmark is deliberately more expensive than a
pull-request smoke test.

### Useful modes

Generate the case directories without running the solver:

```bash
./allRun --generate-only
```

Generate the inputs and print the solver commands:

```bash
./allRun --dry-run
```

Recreate the validation outputs from results already present under
`cases/Re*/`:

```bash
./allRun --postprocess-only
```

## Run individual stages

The scripts can also be called separately.

```bash
python scripts/generate_cases.py
python scripts/run_cases.py --solver /path/to/svmultiphysics --np 8
python scripts/validate_results.py
python scripts/plot_streamlines.py
```

Select cases with `--re`:

```bash
python scripts/generate_cases.py --re 100 400
python scripts/run_cases.py --re 100 400 --np 4
python scripts/validate_results.py --re 100 400
python scripts/plot_streamlines.py --re 100 400
```

`run_cases.py` skips a case when it finds an existing `result_*.vtu` below the case directory. Use `--rerun` to override that behavior. Each solver run is written to `cases/Re*/run.log`.

## Validation calculations

For each Reynolds number, `validate_results.py` selects the numerically
highest `result_<step>.vtu` below the case directory. It extracts the two
centerlines and linearly interpolates the simulated profile to the exact
coordinates listed by Ghia et al.

For literature values `q_i` and simulated values `s_i`, the reported norms are

```text
absolute L2 = sqrt(sum((s_i - q_i)^2))
relative L2 = absolute L2 / sqrt(sum(q_i^2))
RMSE        = sqrt(mean((s_i - q_i)^2))
```

The primary-vortex center is the interior minimum of a reconstructed
streamfunction. The reconstruction averages integrations of
`u = d(psi)/dy` and `v = -d(psi)/dx`, with a linear drift correction that
sets the streamfunction to zero on opposite walls. The vortex error is the Euclidean distance between the simulated and published center coordinates.

The script returns a nonzero status if a relative-L2 or vortex-distance
limit in `benchmark_config.json` is exceeded. Use `--no-fail` only for
exploratory runs where reports are desired despite a failed threshold.

### Initial acceptance limits

| Re | Relative L2 limit, u | Relative L2 limit, v |
|---:|---:|---:|
| 100 | 0.015 | 0.030 |
| 400 | 0.050 | 0.180 |
| 1,000 | 0.080 | 0.120 |
| 5,000 | 0.120 | 0.140 |

The primary-vortex distance limit is `0.020` for every case. These limits
include margin around the current baseline and should be revisited after
results have been collected across supported compilers, solver backends,
and processor counts.

One literature nuance is important: Ghia et al. report the Re = 400
Table-V vortex center from their 257-point solution, whereas this benchmark uses 129-point case. The profile comparisons remain the primary quantitative checks.

## Outputs

`validation/metrics.csv` contains all error norms, thresholds, vortex
coordinates, result steps, and per-case pass/fail status.
`validation/summary.json` provides a compact overall status for automation.
Pointwise centerline comparisons are written under `validation/data/`.

Only these figures are generated:

1. `figure_01_u_vertical_centerline.png`
2. `figure_02_v_horizontal_centerline.png`
3. `figure_03_primary_vortex_center.png`
4. `figure_04_streamlines_Re100.png`
5. `figure_05_streamlines_Re400.png`
6. `figure_06_streamlines_Re1000.png`
7. `figure_07_streamlines_Re5000.png`

The streamline color represents speed. A red plus marks the primary-vortex center extracted by the same algorithm used in the quantitative report.

## Suggested repository use

This benchmark fits a scheduled or manually dispatched workflow:

1. build svMultiPhysics;
2. create a Python environment from `requirements.txt`;
3. run `allRun` with the desired backend and processor count;
4. archive `validation/metrics.csv`, `validation/summary.json`, and the
   seven figures;
5. fail the workflow if `allRun` returns a nonzero status.

## Interpretation

Ghia et al. used a streamfunction-vorticity finite-difference formulation; svMultiPhysics uses a stabilized velocity-pressure finite-element formulation. Exact pointwise equality is not expected. A useful validation requires agreement of the centerline profiles and vortex location, along with stable trends under mesh and time-step refinement.

Reaching the configured final time is not, by itself, evidence that a case has reached steady state.
